Keyword Redact
Site access

Keyword Redact asks for no site access when you install it, and does nothing at all until you grant a site. Open the extension on a site and choose Enable on this site, or grant every site below if you would rather not do it one at a time.

Network responses advanced

Everything above changes how a page looks. This changes the data the page receives, so an application can genuinely misbehave — a redacted identifier may 404, and a stand-in may be written back to the server or into local storage.

It also does not clean the DevTools Network panel, which still shows the original response. Changing this setting takes effect on the next page load.

One per line. * is a wildcard and the pattern must match the whole URL; a line with no wildcard is treated as “contains”. No patterns means no traffic is touched. Matched against the absolute URL.
One per line, restricting which fields are redacted. contacts[*].name for every element, contacts[0].name for one, * for any key at a level, ** for any depth. Naming a key covers its whole subtree. Leave empty to redact every string value in the body. Keys and numbers are never touched, and if you set paths but the response is not JSON, it is left alone.
What this does and does not do

Redaction happens in the page you are looking at. Anyone with access to this browser can read the original by opening DevTools, viewing source, or turning the extension off — so this is for screen sharing, demos and shoulder-surfing, not for withholding data from the person at the keyboard. Text drawn into canvas, video or images has no DOM and cannot be redacted.

Substitute mode changes what a page appears to say, including for you. A plain substitution leaves no visible sign it happened, so turn the dotted underline on if you will be reading the page rather than only showing it.
